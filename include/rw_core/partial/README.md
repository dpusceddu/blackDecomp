# Partial views (include/rw_core/partial/)

Each `Recovered_<Name>.h` here is a **partial view**: the fields of some structure that matched or drafted functions
actually touch, at their PS2 offsets, with opaque `u8 opaque_<offset>[N]` gaps between them and an `assert_` typedef
for every field offset. A view is not a class definition:

- Its extent is the accessed prefix, never the allocation size. Gaps and trailing bytes are unknown, not zero.
- Two views can describe the same object from two groups of functions. Nothing proves that a numeric suffix
  (`IsSet0C`, `Cursor94`) or a similar name means one type, so views are not merged without evidence.
- The first line says `UNVERIFIED` until a matched function reads or writes members through the view, and then names
  that function (`VERIFIED access view by 0x...`).

Why they exist: the automatic pipeline (`tools/autodecomp.py`, `tools/decompile.py`) and some matched C files need a
struct to write `p->field_30` instead of pointer arithmetic, and the compiler needs the exact offsets. The views are
hand-maintained source, edited like any other header. `all.h` (in `include/game/partial/`) includes every view.

Where the real definition is: for a class with RTTI or a vtable, the class header under `include/<library>/classes/`
(generated by `tools/maint/class_skeletons.py`) or a hand-written header next to it (`include/<library>/*.hpp`,
`include/ps2/recovered_types.h`) is the definition to extend. When you learn that a view is a known class, move its
fields into that class header and delete the view in the same commit (keep the offset asserts), then fix its
`#include` lines.
